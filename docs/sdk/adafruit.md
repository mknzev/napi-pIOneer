# Adafruit / CircuitPython

Раздел **Устройства → Adafruit** ищет драйверы в официальном CircuitPython Bundle и устанавливает Python wheels из PyPI. Каталог кэшируется; при недоступном обновлении показываются установленные пакеты. Само наличие драйвера в каталоге не гарантирует совместимость: библиотеки с `displayio`, `neopixel`, `pulseio`, USB/BLE или специфическими API микроконтроллера могут не работать. Проверенные версии отмечаются отдельно.

## Подключить устройство

В редакторе скрипта нажмите **Подключить устройство** или **⌘K / Ctrl+K**. Выберите BME280, SHT4x, SSD1306, PCA9685 или LCD с PCF8574; укажите включённый I²C и адрес. Мастер установит необходимые библиотеки, покажет код и после вставки запишет `adafruit.lock.json`. Из раздела устройств тот же мастер создаёт новый скрипт-пример. Для остальных библиотек можно установить пакет через каталог и написать код по его README.

```python
import board
from adafruit_bme280 import basic

i2c = board.I2C()  # SDA J9-3, SCL J9-5; I2C1
sensor = basic.Adafruit_BME280_I2C(i2c, address=0x76)
print(sensor.temperature, sensor.humidity, sensor.pressure)
i2c.deinit()
```

Доступ к железу выполняется через Pioneer HW и RPC, включая захваты ресурсов. Чужой захват адреса/пина вызывает ошибку; остановка и аварийное завершение worker освобождают ресурсы. В блоке создавать устройство нужно в `setup`, а не при импорте файла. Не обращайтесь к устройству из самостоятельно созданных потоков блока: контекст принадлежит вызовам его жизненного цикла и таймерам `self.every`.

GPIO, зарезервированный pin-параметром блока, доступен его CircuitPython-хендлам в том же проекте. `DigitalInOut` может открыть его как вход и переключать между входом и выходом; резервирование `gpio_out` остаётся эксклюзивным для других проектов и скриптов даже во время работы хендла в режиме входа. `deinit()` освобождает только свой хендл, а остановка или ошибка запуска проекта — также его резервирование. Разные проекты не объединяются по имени; захваты шин и несовместимые режимы GPIO (например, GPIO и soft-PWM) по-прежнему конфликтуют.

Кнопка **Пример из библиотеки** на карточке установленного пакета создаёт скрипт из официального `examples/`, предпочитая `simpletest`. Пример кэшируется для работы офлайн. `board.SDA/SCL/I2C()` уже используют пины Napi-C; другие обозначения пинов замените в редакторе по подсказкам. Пример берётся из текущей ветки репозитория, поэтому для старой версии драйвера его API может отличаться. Скрипт сохраняется, но автоматически не запускается.

## AI-помощник

Помощник в проекте, скрипте и редакторе блока получает актуальный список установленных драйверов и их версий при каждом запросе. Например: «Собери блок BME280 из установленного Adafruit-драйвера: температура, влажность, давление и ошибка чтения». Он может получить список Python-файлов установленной библиотеки, прочитать её API без импорта/исполнения и использовать проверенный шаблон подключения. Если библиотека не установлена, сначала предложит установить её в **Устройства → Adafruit**.

Для визуального проекта новый блок предлагается черновиком: проверьте и сохраните его, затем попросите помощника добавить сохранённый тип в граф и соединить сокеты. После сохранения AI получает схему зарегистрированной ноды; до этого ещё не существующий тип не предлагается в операциях графа. Код не сохраняется и не запускается самим AI. Для фиксации версии используйте мастер подключения; AI не обновляет общий site или lock автоматически.

## API платы

- `board.J9_7` и `board.GPIO2_A4` — один пин; `board.I2C()/SPI()/UART()` — ленивые объекты интерфейсов по умолчанию. После `deinit()` следующий вызов создаст новый объект.
- `busio.I2C` поддерживает блокировку, сканирование, буферы и repeated start; частоту I²C задаёт Device Tree (сейчас 100 кГц). `busio.SPI` — 8 бит, режимы 0–3, аппаратный CS0; библиотека может управлять отдельным CS через GPIO. `UART` — 8N1, timeout до 5 с.
- `digitalio.DigitalInOut`: вход, выход, open drain. На Linux `Pull.UP/DOWN` проверяет pinconf, но не меняет электрическую подтяжку программно. При несовпадении появляется предупреждение; quick-fix в редакторе открывает **Устройства → Ядерные драйверы → Подтяжки GPIO** с выбранным пином. Применение плана и перезагрузка требуют вашего подтверждения. На стенде Pull действует сразу.
- `analogio.AnalogIn.value` — 0…65535, `reference_voltage = 1.8` В. `pwmio.PWMOut` использует включённый аппаратный PWM пина; иначе soft-PWM до 500 Гц с предупреждением. Soft-PWM не гарантирует точность сервопривода.
- Операции шин ограничены 4096 байтами. `microcontroller.cpu.temperature` не реализован и выдаёт понятную ошибку.

GPIO Napi-C рассчитаны на **3,3 В**. Нельзя напрямую соединять SDA/SCL с подтяжками к 5 В. Проверенный LCD2004 с PCF8574 работает при питании всего модуля от 3,3 В: SDA J9-3, SCL J9-5, адрес 0x27. Это результат для конкретного модуля, а не гарантия работы всех LCD на таком питании. Для 20x4 мастер использует смещения строк 0x00/0x40/0x14/0x54, для 16x4 — 0x00/0x40/0x10/0x50.

## Общие версии и обновления

Все проекты используют один активный site `data/drivers/adafruit/site`. Установка выполняется в отдельное поколение и переключает site только после успешного pip и проверки. Настоящие Blinka/PlatformDetect заменены контролируемыми wheel-заглушками; наша прослойка всегда первая в пути импорта. Нативные wheels и настоящая Blinka отклоняются.

Версии прямых и транзитивных зависимостей фиксируются. Несвязанные зависимости не обновляются автоматически; если новая библиотека требует несовместимую версию общей зависимости, установка завершится ошибкой с сохранением прежнего site. Обновление/удаление показывает список использующих драйвер скриптов, блоков и проектов. Уже работающий worker сохраняет прежнее поколение; после остановки и повторного запуска lock должен совпадать с текущими версиями. Обновите подключение через мастер или осознанно измените lock.

Предыдущие поколения сохраняются для работающих процессов. При большом числе обновлений они занимают место; удалять старые `.site-*` допустимо только после остановки всех workers, сохранив поколение, на которое указывает `site`. Lock привязывает драйвер, а общий `.pioneer-adafruit.json` фиксирует все транзитивные версии.

## Блок и модуль

**Создать блок из драйвера** доступно для BME280 (T/H/P), SHT4x (T/RH) и PCA9685 (вход duty 0…65535, канал и частота). Сгенерированный код — обычный Python-блок; ошибки датчика отображаются в состоянии ноды.

Мастер может скачать ZIP с `module.yaml`, `block.py`, `simulation.py`, README и lock. В редакторе блока экспортируется его текущий код; проверьте выбранный драйвер. Импортируйте ZIP во вкладке **Модули**, подтвердив доверие к Python-коду. Перед импортом на другую плату установите указанную в lock версию драйвера во вкладке Adafruit: несовпадение не исправляется скрытым обновлением общего site.

## Стенд и границы проверки

На общем виртуальном стенде доступны протокольные модели BME280, SHT4x, SSD1306 и PCA9685. В Adafruit можно добавить модель на выбранный bus/address, менять температуру/влажность/давление, видеть кадр OLED и состояния PWM. Реальные библиотеки из PyPI работают без изменений; тот же скрипт запускается обычной кнопкой **Запустить**. Для текста SSD1306 используйте `font_name=board.FONT5X8` — шрифт Adafruit входит в Pioneer с MIT-лицензией.

Модели проверяют протокол и значения, не электрическую схему, точные времена измерения или неисправности датчиков. BME280 использует синтетическую калибровку. Бейдж «на стенде» не означает физическую проверку. Аппаратная проверка выполнена на LCD2004; настоящие BME280/OLED сейчас отсутствуют. Отдельный выбор симуляции на каждый запуск и гибрид из идеи 006 — отдельная задача; текущий выбор HAL общий для сервиса.
